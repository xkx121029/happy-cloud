# 文件去重与分片传输优化方案

> 需求原文：_「接下来优化性能，支持分片上传下载，服务端文件智能去重，多用户同文件或共享目录文件只保存一份，向用户展示索引，用户删除只删除索引，不删除源文件」_
>
> 已确认的 4 项决策：① 物理实体在**引用数归零时自动回收**；② 索引展示 = **管理员页 + 用户文件详情**；③ 配额口径 = **按去重后计费（同一内容仅首个引用计配额）**；④ 存量数据 = **一次性迁移**（先 dry-run，附备份说明）。

- 统一响应体 `util.OK` → `{code:0,message:"ok",data}`，`util.Fail` → `{code:非0}`，HTTP 恒 200。

## 二、目标方案总览

1. **全局内容寻址实体层**：物理实体统一存 `blobs/<h[0:2]>/<h[2:4]>/<hash>`（两级散列目录，避免单目录海量文件），新增 `blobs` 表（`hash` 主键、`size`、`ref_count`、`billed_user_id`）作为**并发锁锚点 + 引用计数权威来源**。
2. **全链路引用维护**：所有"产生索引 / 销毁索引"的代码路径统一收敛到 `blob.Acquire` / `blob.Release`；引用归零 → 删除物理实体 + 删除 blob 行。
3. **计费规则（去重后计费）**：实体由**首个引用者**计配额；首个引用者索引消失而实体仍被他人引用时，**计费自动转移**给下一个引用者；归零则退还。
4. **分片/并行/断点**：上传断点续传 + 合并期增量哈希（去掉二次读盘）；下载 Web 原生流式（零内存）+ 可选并行 Range（File System Access API）+ P2P 隧道分片；Android 并行 Range + `.part` 续传。
5. **索引可视化**：用户文件「详情」显示指纹/引用数/是否计费我/节省量；管理员新增「存储索引」页（物理 vs 逻辑占用、blob 列表、引用明细、校验修复、孤儿回收）。
6. **存量迁移**：`cmd/dedup-migrate`（默认 dry-run）搬实体、重写索引路径、重建引用计数与配额，附 `-apply` 前置备份提示。

### 3.2 新增 `backend/internal/blob/blob.go`（核心）

职责：实体存在性、引用登记/释放、计费增减、索引查询。**所有函数都接受 `*gorm.DB`（可为事务）**，保证与索引行同事务提交。

```go
package blob

// Path 返回实体路径
func Path(hash string) string

// Exists 实体是否已在磁盘（用于秒传/写盘前判断）
func Exists(hash string) bool

// Acquire 登记一次引用：
//  1) 确保实体目录存在（写盘由调用方完成，本函数只负责目录）
//  2) INSERT ... ON DUPLICATE KEY UPDATE ref_count = ref_count + 1
//     受影响行数 == 1 表示"新建实体"→ 本用户成为计费者并 +size 配额
//  3) 若已存在且 billed_user_id == 0（上一任计费者已退出）→ 本用户接手计费
// 返回 (后来实际生效的计费用户, 本次是否向本用户收费, error)
// 配额检查用条件更新：WHERE quota_used + ? <= quota_max，失败返回 ErrQuotaExceeded
func Acquire(tx *gorm.DB, userID uint, hash string, size int64) (billed uint, charged bool, err error)

// Release 释放一次引用（调用方需先删除索引行）：
//  1) 行锁读 blob（SELECT ... FOR UPDATE）；不存在则直接返回（兜底：实体不在册）
//  2) ref_count - 1
//  3) 若本用户对该 hash 已无任何索引（含回收站）且 billed_user_id == 本用户：
//       找下一个引用者（SELECT user_id FROM files WHERE hash=? AND type=1 ORDER BY user_id LIMIT 1）
//       有 → 计费转移（退本用户 size、增新用户 size）；无 → billed_user_id = 0 并退还本用户
//  4) 若 ref_count <= 0 → 退还当前计费者 → os.Remove(Path(hash)) → 删除 blob 行
func Release(tx *gorm.DB, userID uint, hash string, size int64) error

// Refs 返回某实体的全部索引（管理端用，含用户名与回收站状态）
func Refs(hash string) ([]RefItem, error)

// Stats 聚合统计：blob 数、物理占用、逻辑占用（SUM(files.size)）、节省量、
// 仅被回收站引用的实体数、计费为空的实体数
func Stats() (StatsResult, error)

// Verify 校验并修复：dry-run 只输出差异报告；apply 时
//   a) 重算 ref_count / billed_user_id
//   b) 按计费关系重算每个用户的 quota_used
//   c) 删除 ref_count<=0 的 blob 行与其物理文件
//   d) 扫描 blobs/ 下无索引引用的孤儿实体（可单独开关 gcOrphans）
func Verify(tx *gorm.DB, apply bool, gcOrphans bool) (Report, error)

var ErrQuotaExceeded = errors.New("存储空间不足")
```

关键实现要点：
- 计费只用**条件更新**：`UPDATE users SET quota_used = quota_used + ? WHERE id = ? AND quota_used + ? <= quota_max`（受影响行数为 0 即超额）。退还用 `GREATEST(quota_used - ?, 0)`（沿用现有写法）。
- `Acquire` 的 upsert 用 `ON DUPLICATE KEY UPDATE ref_count = ref_count + 1, size = VALUES(size), updated_at = NOW()`，靠 `RowsAffected`（1=插入 / 2=更新）区分"是否首次"。
- 所有对 `files` 的计数都带 `type = 1 AND hash = ?`（文件夹 hash 为空，天然不参与）。

### 3.7 存量迁移 `backend/cmd/dedup-migrate/main.go`

CLI（默认 dry-run）：

```
dedup-migrate [-dry-run=true] [-apply] [-keep-legacy=false] [-concurrency=4]
```

执行步骤（全程输出中文报告）：
1. 扫描 `files WHERE type=1 AND storage_path <> ''`，按 `hash` 分组；跳过 `storage_path` 已在 `blobs/` 下的行（幂等，可重复执行）。
2. 每组：目标 `util.BlobPath(hash)`；
   - 目标已存在且 size 一致 → 视为已去重，直接重写索引路径；
   - 目标已存在但 size 不一致 → 记入 `conflicts`，跳过该组（打印 hash 与双方路径），**不覆盖任何文件**；
   - 不存在 → 优先 `os.Rename`（同盘原子），失败则 `copy + fsync + remove`。
3. 写 `blobs` 行：`ref_count` = 组内行数，`size` = 实体大小，`billed_user_id` = 组内 `MIN(user_id)`（= 首个引用者）。
4. `UPDATE files SET storage_path = <blobPath> WHERE id IN (...)`。
5. 重算每个用户 `quota_used` = `SUM(blobs.size WHERE billed_user_id = user)`，并输出 before/after 对照表（说明口径变化：回收站索引仍计费，与 M8 一致）。
6. `-keep-legacy=false`（默认）时清理已空的旧用户目录 `storage/<userID>/`（只删空目录，非空目录仅打印告警）。
7. 退出码：dry-run 恒 0；`-apply` 遇 `conflicts > 0` 返回 2（提示人工处理）。

[docker-compose.yml](file:///d:/xkx/xkx_appproj/happy_teach/happy_cloud/docker-compose.yml)/[Dockerfile](file:///d:/xkx/xkx_appproj/happy_teach/happy_cloud/backend/Dockerfile)：builder 阶段追加 `go build -o dedup-migrate ./cmd/dedup-migrate`，runtime 阶段 `COPY --from=builder /build/dedup-migrate .`，部署后用 `docker compose run --rm backend ./dedup-migrate -dry-run`（`cmd` 覆盖默认 CMD，无需改 compose）。

## 六、验证步骤

### 6.1 构建校验

# web

### 6.2 端到端清单（双用户 A/B + 管理员）

1. **去重落盘**：A 上传一个 ≥1GB 文件 → `docker compose exec backend ls -l /data/happy-cloud/blobs/*/*/` 只有 1 份，大小与源一致；`files` 表该行 `storage_path` 指向 `blobs/...`。
2. **跨用户秒传**：B 上传**同一文件** → 接口返回 `exists:true`；物理文件数不变；`blobs.ref_count = 2`；**B 的 `quota_used` 不变**（B 不计费），A 的 `quota_used` 含该文件。
3. **只删索引不删源**：A 删除该文件（回收站）→ 实体仍在；A 彻底删除 → 实体仍在（B 仍引用），`billed_user_id` 变为 B，配额从 A 退还并记到 B。
4. **归零自动回收**：B 彻底删除 → 实体文件消失、`blobs` 行消失、B 配额退还。
5. **共享目录**：A 共享文件 → B 在公共目录下载得到同一 SHA256，且公共目录不产生新物理文件。
6. **转送**：A 转送给 B → B 接受 → 无新增物理文件，B 配额不变。
7. **上传断点续传**：大文件中途关闭标签 → 重传时 Network 面板中已上传分片被跳过（后端 `upload/status` 命中），最终文件 hash 校验通过。
8. **合并性能**：比较大文件合并耗时与改动前（去掉二次全量读，应有可测量的下降）；`go vet` 无新增告警。
9. **下载零内存**：Web 下载 1GB 文件 → 浏览器内存不增长（DevTools Performance/Memory）；开启并行下载时可见 4 路 Range 请求；下载文件 SHA256 与源一致。
10. **管理员索引页**：物理占用 < 逻辑占用且节省率非零；点击「校验（dry-run）」在无漂移时全部为 0；人为改一条 `ref_count` 后 dry-run 能报出差异、「校验并修复」能修正。
11. **存量迁移**：`docker compose run --rm backend ./dedup-migrate -dry-run` 输出报告（将移动实体数、释放空间、各用户配额 before/after）→ 备份（`mysqldump happy_cloud` + `tar storage`）→ `-apply` → 复查下载/预览/回收站恢复/分享下载均正常。
12. **回归**：P2P 直连徽标仍可切换；隧道下载（含新 `off/len`）正常；旧 Android 客户端（无 off/len）隧道下载不受影响。

## 七、假设与风险（决策已定，实施时按此执行）

1. **跨用户秒传信任客户端 hash**：与现状一致（现状已对同用户信任 hash）。hash 无法反推内容，且仅本人文件/共享文件的 hash 会出现在响应里，可接受。
2. **回收站索引仍持有实体引用** → 仅被回收站引用的实体不会被回收（可恢复性优先，M8 语义保持一致）。管理员页单独统计"仅回收站引用"的实体数，便于人工清空回收站释放空间。
3. **计费口径变化**：迁移会重算所有用户 `quota_used`，数值可能下降（去重收益）或小幅上升（原先未计费的转送副本进入计费）。迁移报告会输出对照表。
4. **存储目录结构变更**：`<userID>/<hash>` → `blobs/xx/yy/<hash>`。迁移完成后旧用户目录清空；`blobPathOf` 提供回退解析，未迁移行仍可读出。
5. **并发安全**：`Acquire`/`Release` 全部收敛到单一包，且在调用方的同一事务内执行；`ref_count` 用 SQL 原子增减，`Release` 用 `SELECT ... FOR UPDATE` 行锁，避免并发归零竞态（双删/漏删）。
6. **`ref_count` 漂移**：提供管理员「校验并修复」，并且 `Release` 判定用 `ref_count <= 0`（容错而非严格等于）。
7. **P2P 帧协议**：仅新增可选字段，未升级的老客户端行为不变。
8. **`billed_user_id = 0` 的实体**：允许存在（上一任计费者退出且无剩余索引时本应删除，仅在异常路径出现）；`Verify` 会报出数量并可用"下一个引用者接手"修正。
9. 不引入 Redis 缓存/后台定时 GC 任务：所有回收都在删除路径同步完成，孤儿由管理员页手动触发 `gc_orphans`（保持系统简单，避免新增常驻组件）。
